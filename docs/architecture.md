# bentwire architecture and build rules

This file is the shared contract for everyone building v1. `docs/spec.md` is the behaviour, `docs/character-format.md` the format. This file adds the
crate layout, file ownership, cross-cutting decisions and working rules.

## 1. Crates

The planned layout, with two extra crates (reason: the behaviour core and the renderer
are large, have no I/O and are tested on their own; separate crates give each one owner
and keep `bentwired` a thin shell around backends).

| Crate | Role | Depends on |
|---|---|---|
| `crates/agent-formats` | Parsers: ACS 2.0, ACF/ACA 2.0, Agent 1.5 (OLE ACS, ACF/AAF), ACT. Publishable, no daemon deps. Parse to faithful source structures; no conversion policy. | - |
| `crates/agent-fixtures` | `publish = false`. Writers that emit valid ACS, ACF/ACA, ACF/AAF, ACT files from synthetic pictures (tests only). | - |
| `crates/bentwire-character` | Manifest model (plain structs, hand-written TOML mapping), reader for folder and `.bwc`, writer, compositor (character-format 5.3), canonical dump (character-format 11.1), interpreter B (traces), validation, FLAC/WAVE decode. | - |
| `crates/bentwire-convert` | Source structures to bentwire characters; MS ADPCM rule; WMF rasteriser (`src/wmf/`); round-trip check. | agent-formats, bentwire-character |
| `crates/bentwire-core` | Deterministic behaviour core (spec section 2, B-CORE-1): clock, draws and input events in; scene, sound commands, replies and signals out. No I/O. Own playback model; the manifest adapter is in `bentwired/src/model.rs`. | - |
| `crates/bentwire-render` | Software rendering: character picture to buffers, Agent balloon, Office balloon (own look-alike, or a balloon theme from a pack), XP-style menu, text with the bundled Tahoma. Implements the core's text-metrics trait. | bentwire-character, bentwire-core |
| `crates/bentwired` | The daemon: discovery, config/state files, Wayland backend (smithay-client-toolkit, layer-shell), headless backend (spec T-4), zbus API, ksni tray, rodio audio. | core, render, character |
| `crates/bentwire` | CLI (spec 5.5): thin zbus client, plus local `convert`. | bentwire-convert |
| `clients/` | `clients/shell/` (bash and zsh), `clients/claude-code/` (hooks). Use the CLI only. | - |
| `characters/builtin/` | CC0 placeholder pack, generated by `cargo run -p bentwire-convert --bin gen-builtin` (or equivalent), output committed. | - |
| `bentwire-classics` (sibling repository) | The `classics` pack: converted Microsoft characters plus the Office balloon theme, README, `regenerate.sh`, `sources.sh`. Not part of this repository; see 4. | - |
| `assets/fonts/` | Wine Tahoma, LGPL, pinned by hash. | - |

## 2. Cross-cutting decisions (bentwire decisions; also listed in spec.md 3.14)

**A-PACK-1 Packs and search paths.** (Extends B-CHAR-1.)
- A search root is a directory `R`. The roots, in order: each entry of config key
  `character_paths` (list of directories, B-CFG-1 extension), `$XDG_DATA_HOME/bentwire`,
  then each `$XDG_DATA_DIRS` entry plus `/bentwire`. `bentwired --characters DIR`
  (repeatable) prepends roots for development and tests.
- In `R/characters/` every entry is a character (folder with `character.toml`, or
  `*.bwc`) as in B-CHAR-1, or a **pack**: a folder with `pack.toml`, whose direct
  children are characters (and optionally a balloon theme, A-THEME-1). A root may
  also be a `characters/` directory itself or a single pack folder: the loader checks
  for `pack.toml` / `character.toml` first. Entries are visited in sorted name order;
  the first character with a given id wins.
- `pack.toml`: `name`, `licence` (SPDX or free text), `provenance` (free text),
  optional `description`. The daemon hardcodes no pack.
- Installing for a user: copy (or symlink) `characters/builtin` to
  `~/.local/share/bentwire/characters/`, and clone the `bentwire-classics` repository into
  `~/.local/share/bentwire/characters/classics`.

**A-ID-1 Character ids in classics** (the pack in the `bentwire-classics` repository). Ids
are unique across the pack:
- ACS 2.0: file stem, lowercased (`clippit` is the Office XP/2000 Clippit, which is
  the default character, B-CHAR-4).
- ACF/ACA web characters: `<stem>-web`; Agent 1.5: `<stem>-15`; ACT: `<stem>-97` for
  Office 97 actors, `<stem>-bob` for Microsoft Bob actors, other ACT `<stem>-act`.
  A parenthesised qualifier in the file name is dropped while the id stays unique and
  kept on a collision; byte-identical sources are converted once (spec 3.14 A-CONV-5,
  which refines this rule).
- The placeholder in `builtin` has id `bentwire-placeholder` (A-CHAR-1 below).

**A-PACK-2 Which characters go into classics.** Generated, not listed: a source goes in
when conversion succeeds and `source.missing_animations` is empty (character-format D8
"only complete characters"). `regenerate.sh` in `bentwire-classics` prints every excluded
source with the reason; its generated `CONTENTS.md` lists them, if any.

**A-CHAR-1 Fallback default.** B-CHAR-4 step 3 is `clippit`; when it is absent the
daemon falls through to step 4 (first id in sorted order), which with only `builtin`
installed is `bentwire-placeholder`.

**A-THEME-1 Office balloon theme.** A pack may contain `balloon-themes/<id>/theme.toml`
with PNGs (button strips, bullets, icons) extracted from `OBALLOON.DLL` at pack
generation time. The renderer has a generic theme loader; without a theme found through
the pack search it draws its own look-alike (B-OB-1). Golden images in the code repo use
only the look-alike.

**A-TEST-1 Environment variables for real-data tests.**
- `BENTWIRE_SOURCES` = one or more directories (colon-separated) with your own copies of
  the original character files and DLLs, in any layout. Files are found by file name and
  checked by SHA-256 against `docs/sources.md` (the pack's own list is `sources.sh` in
  `bentwire-classics`).
- `BENTWIRE_REFERENCE` = a directory with the Python reference parsers and prototype used
  as test oracle (not public). Tests and scripts find the files they need by file name
  below it (`acs.py`, `acfparse.py`, `agentlz.py`, `cfb.py`, `actparse.py`, the
  prototype's `oracle.py`).
- `BENTWIRE_CLASSICS` = a checkout of `bentwire-classics` (default `../bentwire-classics`).
- `BENTWIRE_PACKS` = a `characters/` directory with packs, for the daemon's load-every-
  character test (`scripts/oracle-check.sh` defaults it to a temp directory holding
  `characters/builtin` and the classics pack).
- Optional: `BENTWIRE_PROTO_COPY` = an existing scratch copy of the prototype (the
  directory holding `oracle.py`);
  `TMPDIR` on disk when `/tmp` is a small tmpfs.
- These names replace spec T-0's `BENTWIRE_SAMPLES` (original files and reference
  parsers are separate inputs); see spec 3.14 A-TEST-1.
- Real-data tests are `#[ignore]` and are run with `cargo test --workspace -- --ignored`
  or `scripts/oracle-check.sh`. When a needed variable is unset, an ignored test
  **panics** with "NOT RUN: set BENTWIRE_…" (so it can never count as passed) and
  `scripts/oracle-check.sh` prints "NOT RUN" and exits 77. Plain `cargo test` never
  touches real data.
- Results and converted output of real data go to a temp directory or to the
  `bentwire-classics` repository, never into tests or other paths of this repository.

**A-TEST-2 Oracle comparison.** The Rust dump and traces are compared against the
Python prototype `oracle.py` in `$BENTWIRE_REFERENCE` (canonical dump and
interpreter A), driven by our own driver script `scripts/oracle/dump.py`, which writes
JSON to a temp dir. The draw source for traces is a shared generator defined in that
driver and mirrored in Rust (splitmix64; `draw(s) = next() % s`), not Python's
`random`. The driver must run against a scratch copy of the prototype (it writes
pickles into `cache/`), with `PYTHONDONTWRITEBYTECODE=1` and `python3 -I`; never write
into `$BENTWIRE_REFERENCE` or `$BENTWIRE_SOURCES`.
- ACT state names: the oracle uses Office 97 type-library names, the Rust converter XP
  names (D6). The comparison maps both through `office97.ids`; it is never loosened.
- WMF characters: no pixel oracle. Checked by golden images produced by our rasteriser
  (kept in `bentwire-classics` or outside the repositories, since they are
  Microsoft-derived) plus structural checks.

**A-TEST-3 Test interface on real backends.** `org.bentwire.Test1` is exported in
headless mode, and on the Wayland backend only with `bentwired --test-interface`
(there only `Pointer`, `Key` (synthetic events fed into the core) and `Snapshot() -> s`
returning the JSON scene: surfaces, positions, sizes, mapped state; `Snapshot` also
exists in headless mode, spec 3.14 A-DESK-3). This lets the desktop scenario answer `ask` through D-Bus under KWin and sway.

**A-FONT-1** The renderer loads `assets/fonts/tahoma.ttf` / `tahomabd.ttf` by path
(compiled in with `include_bytes!`) and tests assert their SHA-256 (see
`assets/fonts/README.md`). fontconfig is used only for a character's own
`balloon.font` (B-BAL-2) at run time, never in golden tests.

## 3. Clean room (binding for every contributor)

- **Allowed to read:** `docs/`; the Python reference parsers in `$BENTWIRE_REFERENCE`
  (`acs.py`, `render.py`, `checks.py` for ACS; `acfparse.py`, `agentlz.py` for ACF;
  `cfb.py` and the Agent 1.5 scripts; `actparse.py` and the other ACT scripts except
  `disasm.py`); the prototype (its Python modules, schema, `harness/`); sample files as
  data.
- **Off-limits:** any disassembly or decompiler output (`*.asm`, `*_decomp*`,
  `*_c`/`*_nc.c`, Ghidra projects, REA exports, `disasm.py`), the analysis work files of
  the Microsoft DLLs, the working copy of the ADPCM codec; REA or any disassembler on
  Microsoft binaries; web searches for Microsoft or third-party Agent source code. Do not
  grep recursively over `$BENTWIRE_REFERENCE`; open the allowed files by name.
- `$BENTWIRE_SOURCES` and `$BENTWIRE_REFERENCE` are **read-only**. Extract archives into
  a `mktemp -d` directory.
- If the docs leave a gap: pick a sensible behaviour, add it to `docs/spec.md` 3.14 as
  a "bentwire decision" with a reason, and report it.

## 4. Data boundary and commits

- No Microsoft data in this repository; it lives only in `bentwire-classics`: no character
  files, images, sounds, palettes, tip texts, golden hashes or golden images derived from
  them in code, tests or docs. Tests use synthetic fixtures from `agent-fixtures` or
  hand-made characters. Allowed exceptions: the lip-sync table, the menu/button/dialog
  captions the spec lists, and the provenance hashes of the source files in
  `docs/sources.md` and `docs/research/`.
- The `classics` pack is its own repository, `bentwire-classics` (split from this one for
  0.1.0, with the history of its folder). Changes to the pack are committed there.
- Stage explicit paths; small commits that build; no history rewriting.
- Do not use "Clippy" as a product name.

## 5. Checks

`cargo build --workspace`, `cargo test --workspace`,
`cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --check`.
Every behaviour test names its rule ID in the test name or a comment
(`#[test] fn r_anim_2_frame_clock()`).
